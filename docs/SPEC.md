# Fahrzeugmarkt — build spec

Prototype of a German-market used-vehicle marketplace. Portfolio piece. UI language: English. Data conventions: German market (EUR, km, kW with PS alongside, first registration, next inspection/HU date).

This file is the single contract between backend, frontend, and infra. Do not deviate from names, routes, or shapes without updating this file.

## Ports and profiles

- Backend: **8080**, context path `/` (all endpoints under `/api/...`)
- Frontend dev: Vite **5173**, proxies `/api` → `http://localhost:8080`
- Docker compose: `web` (nginx) published at **http://localhost:3000**, serves SPA + proxies `/api` → `api:8080`; `db` internal only
- Spring profiles:
  - default: real PostgreSQL from env `DB_URL`, `DB_USER`, `DB_PASSWORD` (compose sets them)
  - `local`: Zonky embedded Postgres auto-started in-process (a `@Profile("local")` `DataSource` bean, zonky dep in normal scope). `./mvnw spring-boot:run -Dspring-boot.run.profiles=local` must work with no DB installed.
- Uploads dir: env `UPLOAD_DIR`, default `./uploads` (compose mounts a volume)

## Roles and auth

Session-cookie auth (Spring Security, `SecurityFilterChain`, BCrypt, CSRF disabled — prototype, documented). Roles: `BUYER`, `SELLER`, `ADMIN`.

- `POST /api/auth/register` `{email, password, displayName, role}` role ∈ BUYER|SELLER → 201 + logs in (sets session)
- `POST /api/auth/login` `{email, password}` → 200 `UserDto` | 401
- `POST /api/auth/logout` → 204
- `GET /api/auth/me` → 200 `UserDto` | 401
- `UserDto = {id, email, displayName, role, city}`

Route protection: browse/detail/meta/facets public. Saved + contact require login. Listing CRUD requires SELLER and ownership. `/api/admin/**` requires ADMIN.

## Database (Flyway, PostgreSQL dialect)

`V1__schema.sql` (DDL + indexes, every index gets a `-- purpose:` comment), `V2__seed_data.sql` (generated by `scripts/generate-seed.mjs`, committed).

Normalized schema:

- `makes(id BIGSERIAL PK, name TEXT UNIQUE NOT NULL)`
- `models(id BIGSERIAL PK, make_id FK→makes NOT NULL, name TEXT NOT NULL, UNIQUE(make_id, name))`
- `users(id BIGSERIAL PK, email CITEXT/TEXT UNIQUE NOT NULL, password_hash TEXT NOT NULL, display_name TEXT NOT NULL, role TEXT NOT NULL CHECK in BUYER/SELLER/ADMIN, phone TEXT, city TEXT, created_at TIMESTAMPTZ NOT NULL DEFAULT now())`
- `vehicles(id BIGSERIAL PK, model_id FK→models NOT NULL, body_type TEXT NOT NULL, fuel_type TEXT NOT NULL, transmission TEXT NOT NULL, color TEXT NOT NULL, mileage_km INT NOT NULL, power_kw INT NOT NULL, doors INT, seats INT, first_registration DATE NOT NULL, next_inspection DATE, description-free — descriptions live on listing)`
- `listings(id BIGSERIAL PK, vehicle_id FK→vehicles UNIQUE NOT NULL, seller_id FK→users NOT NULL, title TEXT NOT NULL, description TEXT NOT NULL, price_eur NUMERIC(10,2) NOT NULL CHECK > 0, status TEXT NOT NULL DEFAULT 'ACTIVE' CHECK in ACTIVE/FLAGGED/REMOVED, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), updated_at TIMESTAMPTZ NOT NULL DEFAULT now())`
- `listing_images(id BIGSERIAL PK, listing_id FK→listings ON DELETE CASCADE NOT NULL, url TEXT NOT NULL, sort_order INT NOT NULL DEFAULT 0)` — `sort_order = 0` is the cover image
- `saved_listings(user_id FK→users, listing_id FK→listings ON DELETE CASCADE, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), PK(user_id, listing_id))`
- `inquiries(id BIGSERIAL PK, listing_id FK→listings ON DELETE CASCADE NOT NULL, sender_name TEXT NOT NULL, sender_email TEXT NOT NULL, message TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now())`

Enum string values (uppercase in DB and API):
- fuel: `PETROL, DIESEL, ELECTRIC, HYBRID, PLUG_IN_HYBRID, LPG`
- transmission: `MANUAL, AUTOMATIC`
- body: `SEDAN, ESTATE, HATCHBACK, SUV, COUPE, CONVERTIBLE, VAN, PICKUP`

Indexes to create (with purpose comments): listings `(status, created_at DESC)` for default browse; listings `(price_eur)`; listings `(seller_id)`; vehicles `(model_id)`, `(mileage_km)`, `(power_kw)`, `(first_registration)`, `(fuel_type)`, `(transmission)`, `(body_type)`; models `(make_id)`; saved_listings `(listing_id)`; inquiries `(listing_id)`.

Filtering/sorting is ALWAYS SQL-side (JPA Specifications joining listings→vehicles→models→makes). Never filter in memory.

## Seed data

`scripts/generate-seed.mjs` (deterministic, seeded PRNG, no Date.now) emits `backend/src/main/resources/db/migration/V2__seed_data.sql`:

- ~24 model lines across German-market makes: VW (Golf, Passat, Tiguan, Polo, ID.3), BMW (3 Series, 5 Series, X3, 1 Series), Mercedes-Benz (C-Class, E-Class, GLC, A-Class), Audi (A3, A4, A6, Q5), Opel (Corsa, Astra), Ford (Focus, Fiesta), Škoda (Octavia, Fabia), Toyota (Corolla, Yaris), Renault (Clio), Hyundai (i30), Tesla (Model 3)
- **220 listings**, one vehicle each. Realistic correlations: first_registration 2008–2025; mileage grows with age (roughly 8k–20k km/yr with noise); price falls with age/mileage and scales with model class (Polo 3–18k, 5 Series 8–60k, Tesla 25–55k…); power_kw realistic per model (Polo 55–85, 5 Series 135–250…). ELECTRIC only for ID.3/Model 3 (and transmission AUTOMATIC). next_inspection between 2026-08 and 2028-06 for most, a few NULL.
- Titles like "BMW 3 Series 320d Sport Line", descriptions 2–3 varied sentences, English.
- Sellers: 12 users (mix "dealer-style" and private, cities: Hamburg, Norderstedt, Pinneberg, Lübeck, Kiel, Bremen, Buchholz, Elmshorn), each owning 15–25 listings.
- Demo accounts (README-documented): `buyer@demo.de`, `seller@demo.de` (owns ~8 listings), `admin@demo.de`, all password `demo1234` (single precomputed BCrypt hash constant in the generator). A few pre-saved listings for the demo buyer. 2 listings pre-FLAGGED so admin queue isn't empty.
- Images: every listing gets 2–3 `listing_images` rows with urls `/api/images/seed/{vehicleId}-{n}.svg` (n = 0..2).
- Wrap in one transaction; fix sequences with `setval` at the end.

## Seed images (no binaries in repo)

`GET /api/images/seed/{vehicleId}-{n}.svg` → backend generates a deterministic SVG (seeded by vehicleId+n): layered gradient backdrop + clean side-profile car silhouette path chosen by body_type, tinted by vehicle color, subtle ground shadow, angle/framing varies with n. Must look intentional and consistent, not clip-art. Cache-Control: long max-age. 404 if vehicle missing.

Uploaded images: `POST /api/listings/{id}/images` (multipart `file`, jpeg/png/webp, ≤5 MB, max 10 per listing) stores to `UPLOAD_DIR` with random filename → row with url `/api/images/upload/{filename}`; served with correct content type. `DELETE /api/images/{imageId}` (owner only).

## Search API (the centerpiece)

`GET /api/listings` query params, all optional, combinable:
`make` (name), `model` (name), `yearFrom`, `yearTo` (first_registration year), `priceFrom`, `priceTo`, `mileageFrom`, `mileageTo`, `powerFrom`, `powerTo` (kW), `fuelType`, `transmission`, `bodyType` (each may repeat: `fuelType=PETROL&fuelType=DIESEL` = OR within dimension, AND across dimensions), `q` (ILIKE against title/make/model), `sort` ∈ `newest` (default) | `price_asc` | `price_desc` | `mileage_asc` | `year_desc`, `page` (0-based, default 0), `size` (default 24, max 60). Only `status = ACTIVE` listings.

→ `200 {content: ListingCardDto[], page, size, totalElements, totalPages}`

`ListingCardDto = {id, title, make, model, priceEur, firstRegistration, mileageKm, powerKw, fuelType, transmission, bodyType, city, coverImageUrl, createdAt}`

`GET /api/listings/facets` same filter params → `{makes: [{value, count}], fuelTypes: [...], transmissions: [...], bodyTypes: [...]}` — counts of ACTIVE listings matching all filters EXCEPT the counted dimension (standard faceting), GROUP BY in SQL.

`GET /api/listings/{id}` → `ListingDetailDto = {id, title, description, priceEur, status, createdAt, vehicle: {make, model, bodyType, fuelType, transmission, color, mileageKm, powerKw, doors, seats, firstRegistration, nextInspection}, seller: {id, displayName, city, phone, memberSince}, images: [{id, url, sortOrder}], savedByMe: bool}`

`GET /api/meta` → `{makes: [{name, models: [name]}], fuelTypes, transmissions, bodyTypes, sorts}` for filter UI.

## Seller + buyer + admin API

- `POST /api/listings` (SELLER) `{title, description, priceEur, vehicle:{makeName, modelName, bodyType, fuelType, transmission, color, mileageKm, powerKw, doors, seats, firstRegistration, nextInspection}}` → 201 detail. Unknown make/model names are created (normalized insert-if-absent).
- `PUT /api/listings/{id}` same body (owner) → 200; `DELETE /api/listings/{id}` (owner) → 204 (hard delete, cascades)
- `GET /api/seller/listings` (SELLER) → own listings all statuses, each `{...ListingCardDto, status, imageCount, inquiryCount, savedCount}`
- `GET /api/seller/inquiries` (SELLER) → inquiries for own listings, newest first
- `POST /api/listings/{id}/contact` (any logged-in user) `{name, email, message}` → 201 (stored; no real email — prototype)
- `GET /api/saved` (auth) → ListingCardDto[]; `PUT /api/saved/{listingId}` → 204; `DELETE /api/saved/{listingId}` → 204
- Admin: `GET /api/admin/listings?status=` → all listings w/ seller email; `POST /api/admin/listings/{id}/flag` → status FLAGGED; `POST /api/admin/listings/{id}/approve` → status ACTIVE. FLAGGED/REMOVED hidden from public browse/detail; seller still sees own with badge.

Errors: JSON `{status, message, fieldErrors?: {field: msg}}` via `@RestControllerAdvice`; bean validation on all request bodies.

## Frontend

Vue 3 Composition API + `<script setup lang="ts">` only. Pinia (auth store, saved store), vue-router (history mode). No UI framework — hand-rolled design system, scoped styles + CSS custom properties. Types for all DTOs in `src/types.ts` mirroring this spec. One `src/api/client.ts` fetch wrapper (credentials: 'include', JSON errors typed).

Pages (routes): `/` browse grid; `/listing/:id` detail; `/login`, `/register`; `/saved` (buyer, guarded); `/sell` dashboard (seller, guarded); `/sell/new`, `/sell/:id/edit` listing form; `/admin` moderation queue (admin, guarded). Router guard redirects to /login with return param; nav shows role-appropriate links.

Browse page: responsive card grid (1/2/3/4 cols), left filter sidebar ≥1024px, slide-in sheet below; filter chips row showing active filters with × to remove and "Clear all"; sort dropdown; pagination controls; result count ("312 vehicles"); skeleton cards while loading; designed empty state with reset action. Filters: make → model (dependent select), year range, price range, mileage range, power range, fuel checkboxes with facet counts, transmission, body type chips. Debounced apply, state synced to URL query so results are shareable/back-button-safe.

Card: cover image, title, price prominent, spec line "EZ 03/2019 · 68.500 km · 110 kW (150 PS) · Diesel · Automatic", city, save-heart toggle, "New" badge if < 7 days.

Detail: gallery (main image + thumbnails, keyboard arrows, counter), price panel with save button, full spec table (two-column, all vehicle fields incl. first registration "03/2019", next inspection "HU 06/2027", power "110 kW (150 PS)"), description, seller card, contact form (validation, success state), back-to-results link preserving query.

Seller dashboard: table/cards of own listings w/ status badge (Active/Flagged/Removed), image count, saved count, inquiry count, edit/delete (confirm dialog), link to inquiries list. Listing form: two-step-feel single page (vehicle facts, then listing text+price), all validations inline, image upload with drag-drop + previews + delete, edit mode prefills.

Admin: queue table, flag/approve actions with optimistic update.

Formatting helpers (single `src/format.ts`): price `Intl.NumberFormat('de-DE', {style:'currency', currency:'EUR', maximumFractionDigits:0})` → "24.990 €"; mileage `de-DE` + " km"; power `"${kw} kW (${Math.round(kw*1.35962)} PS)"`; dates "MM/YYYY" for first registration, "MM/YYYY" for HU.

### Visual system

Recruiter-facing. Tokens in `src/styles/tokens.css`: 4px spacing scale; type scale 13/14/16/18/22/28/36; radius 6/10/16; system font stack. Light + dark via `prefers-color-scheme` AND a manual toggle (persisted, `data-theme` attr wins). Palette: neutral surface ramp + one confident accent (deep petrol/teal family) + semantic green/amber/red for status badges. Both themes must pass contrast. Consistent focus rings. Subtle transitions (150–200ms) on hover/theme. Mobile-first responsive. No emoji as icons — small inline SVG icon set. Copy rules: no em dashes anywhere, headings without trailing periods.
